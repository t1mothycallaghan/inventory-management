Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talks to a FastAPI backend over REST. The backend serves in-memory mock data loaded from JSON files. There is no database.

System Architecture

Three tiers that run locally. The browser calls the API directly at http://localhost:8001/api. Vite has no dev proxy, so the backend's CORS setting allows all origins.

Data Flow

What happens when a user changes a filter, for example selecting a warehouse on the Dashboard.

User selects a filter

FilterBar binds to four shared refs: period, location, category and status. The refs are defined at module level, so every view shares a single filter state.

client/src/components/FilterBar.vue · composables/useFilters.js

View reacts and requests data

A watcher in the view calls getCurrentFilters(), which maps the UI names to API names (location to warehouse, period to month). The view then calls the matching api.* methods, often several at once.

client/src/views/Dashboard.vue

API client builds the request

api.js leaves out any filter set to 'all', builds a query string with URLSearchParams, and sends an axios GET.

client/src/api.js → GET /api/dashboard/summary?warehouse=...

FastAPI filters in memory

The handler runs apply_filters() for warehouse and category (exact or case-insensitive match) and status. It then runs filter_by_month(), which accepts a single month such as 2025-03 or a quarter such as Q1-2025. Some endpoints also calculate aggregates, such as inventory value and low-stock count.

server/main.py · data from server/mock_data.py

Pydantic validates the response

List and detail endpoints declare a response_model, so the returned data is checked against the models. Dashboard, spending and report endpoints return plain dicts.

UI derives display data

The JSON response is stored in refs. Computed properties derive the KPIs, chart data and tables from those refs. useI18n translates labels and formats currency for English or Japanese.

Frontend Structure

How state and responsibilities are split in the client.

Shared state (composables)

  • useFilters: global filter refs, hasActiveFilters, resetFilters(), getCurrentFilters()
  • useI18n: locale switching between en and ja, translation, currency, translated product and warehouse names
  • useAuth: a mock current user for the profile menu. There is no real authentication.

App shell

  • App.vue: top navigation, FilterBar, profile and language controls, the tasks modal, and the global styles
  • main.js: creates the router and its six routes and mounts the app
  • Pages live in views/. Reusable modals and controls live in components/.
  • utils/currency.js holds the currency formatting helpers

Known Gaps

Mismatches I found while comparing the client code with the server code.

Task endpoints are missing on the backend

App.vue calls getTasks, createTask, deleteTask and toggleTask. These map to GETPOSTDELETEPATCH /api/tasks, but server/main.py defines none of those routes, so every call returns 404.

Purchase order endpoints are missing on the backend

api.js defines POST /api/purchase-orders and GET /api/purchase-orders/{backlogItemId}, but neither route exists on the server. No component calls these methods yet, so nothing breaks today. The CreatePurchaseOrderRequest model is declared and never used.

Backlog view is not routed

views/Backlog.vue exists, but main.js registers no route for it.

Reports bypasses the API client

Reports.vue calls axios with a hardcoded http://localhost:8001 URL instead of going through api.js. The base URL is also hardcoded in api.js, so there is no environment-based configuration.

Hardcoded year in date filters

QUARTER_MAP and the quarterly report only recognise dates in 2025. Orders from other years are left out of quarterly filtering and reports.
